## 1. 產品定位

本網站不是單純的課程目錄，也不是心理測驗或正式選課系統，而是一個讓高中生與一般訪客理解本學系的「四年課程與學習探索地圖」。

網站必須同時完成三項任務：

1. 讓使用者快速理解本學系在做什麼。
2. 讓使用者看懂大一至大四的課程與能力累積。
3. 讓使用者依照自己的興趣探索可能的學習路徑與成果。

核心產品命題：

> **以課程地圖建立可信度，以興趣探索提供自主性，以真實作品形成歸屬感。**

## 2. 背景與問題定義

### 2.1 對外溝通的主要問題

本學系具有文學、語文、文化、數位人文、文化創意、社會設計與實作課程，但若直接以「人文為本」或「從人文出發」作為網站第一層敘事，可能使高中生將本系理解為傳統中文系或台文系。

另一方面，如果只強調AI、數位內容、設計與文化創意，又可能使本系看起來像一般數位內容或文創設計學系，失去人文深度與學系特色。

### 2.2 目標使用者的主要疑問

高中二、三年級學生在選系時通常會詢問：

- 這個系到底在學什麼？
- 會不會只是傳統文科？
- 我可以做數位內容、AI、影像、策展或地方文化嗎？
- 四年會怎麼逐步學習？
- 哪些是必修？哪些可以自由選擇？
- 我最後能拿出什麼作品？
- 這個系是否有和我相似的人？

### 2.3 產品需要解決的核心矛盾

網站必須同時呈現：

- 開放與結構
- 自主與引導
- 人文根基與跨域應用
- 探索感與課程真實性
- 招生吸引力與資訊可信度

## 3. 產品目標

### 3.1 主要目標

1. 讓使用者在10秒內理解本學系不是傳統單一人文學系。
2. 讓使用者在1分鐘內理解兩大學習方向與學習成果。
3. 讓使用者在3分鐘內看懂四年課程與學習能力如何累積。
4. 讓使用者可以依興趣探索課程，不必登入或填寫個人資料。
5. 讓使用者產生「我可以在這裡發展」的初步歸屬感。
6. 讓招生、系所介紹與課程地圖使用同一套資訊邏輯，避免互相矛盾。

### 3.2 非目標

第一版不處理：

- 正式選課
- 學分試算
- 學生登入與個人帳號
- 正式性向測驗
- 固定分流或招生分組
- 系內教師課程審查後台
- 完整課程註冊與先修條件判定

## 4. 目標使用者

### 4.1 主要使用者

#### A. 高中二、三年級學生

具有以下任一特徵：

- 對傳統人文、文學、語文有興趣。
- 不喜歡理工科，但尚未確定是否喜歡人文。
- 不排斥人文，喜歡探索不同可能。
- 喜歡影像、社群、設計、AI或數位內容。
- 成績或志向不適合理工科，希望選擇較有特色的學系。

### 4.2 次要使用者

- 高中生家長
- 高中教師與輔導教師
- 對本學系有興趣的轉學生或跨域學習者
- 校內招生與系所行政人員

### 4.3 不應假設的使用者特質

網站不可假設使用者：

- 已經理解「跨域人文」的意義。
- 已經知道自己未來想做什麼。
- 願意閱讀長篇系所介紹。
- 會先研究「1＋3」課程模組。
- 對「人文」一詞具有正向或明確的理解。

## 5. 核心敘事與品牌語言

### 5.1 首頁主標

建議主標：

> **你想做什麼？這裡不只有一種走法。**

### 5.2 首頁副標

> 從文字、文化與社會議題出發，學習把想法做成內容、設計與行動。

### 5.3 四年主線

> **探索與基礎 → 方法與議題 → 跨域設計與實作 → 成果整合與展現**

### 5.4 核心說明

網站後段再說明：

> 我們從文字、文化與社會議題出發，學習理解問題、進行探究，並將理解轉化為數位內容、設計方案與真實行動。

### 5.5 必須避免的語言

避免將以下語句作為首頁主敘事：

- 從人文出發，走向跨域應用。
- 培養具有人文素養的跨域人才。
- 人文為本、跨域為用、實踐為核心。

以上語句可保留在理念說明或網站後段，但不適合作為高中生第一眼看到的主要訊息。

## 6. 產品資訊架構

網站採單頁結構，提供不同入口，共用同一份正式課程與學習地圖。興趣探索是地圖的操作方式，不是必經問卷或另一份推薦地圖。

### 6.1 頁面閱讀順序

1. 首頁：學系名稱、具體說明、雙入口與可核實的成果摘要。
2. 四年學習總覽：四個階段、閱讀／探究／設計／實作，以及兩大方向的白話說明。
3. 互動課程地圖：年級、共同必修、代表性選修、方向與興趣控制，以及課程詳情。
4. 真實作品與學生故事：作品連回課程，呈現學習過程。
5. 人文理念與實用資訊：課程完整清單、資料版本、系所及招生官方連結。

### 6.2 地圖內的個人探索

使用者可以直接瀏覽，或選擇興趣後查看相關課程、能力與作品。兩種方式保留相同四年結構與共同必修。「我的探索清單」表示自行收藏的課程，不表示已安排正式修課路徑。

### 6.3 導覽

桌機採簡潔頁首錨點；手機以「四年地圖／興趣探索／作品與故事」作為同頁入口。「興趣探索」移至地圖控制區，不開啟獨立流程。是否在離開首頁後顯示固定底部導覽列，須以原型測試決定；不得遮住課程、面板或操作按鈕。

## 7. 網站主要頁面與功能

### 7.1 首頁 Hero 區

#### 內容

- 主標
- 副標
- 「開始探索」按鈕
- 「直接看四年課程地圖」按鈕
- 四項快速資訊：共同必修、兩大方向、專題實習、作品集

#### 目的

- 讓使用者快速理解本學系的外部定位。
- 同時提供探索型與資訊型使用者入口。
- 「開始探索」移至同一地圖的興趣控制區；「直接看四年課程地圖」移至地圖總覽。兩者均無前置問答。
- 現有主標為測試候選，不視為定稿。副標須具體說明學習內容；成果摘要只能使用已核實資料。

### 7.2 「這個系會做什麼」區

使用四個動詞呈現：

1. 閱讀：理解文本、文化與社會現象。
2. 探究：進行田野調查、資料分析與議題研究。
3. 設計：將故事、文化與問題轉化為內容與方案。
4. 實作：透過專題、策展、實習與場域合作完成作品。

每個動詞應連結至相關課程與作品。

### 7.3 兩大學習方向區

#### 數位創意與內容設計

白話副標：

> 做出數位內容、互動作品與文化創意。

#### 文化永續與社會應用

白話副標：

> 走進地方與文化現場，做田野、策展、品牌與文化企劃。

固定說明：

> 兩大方向不是招生分組，也不是固定分流；學生可以依興趣跨方向修課，組合自己的學習路徑。

### 7.4 四年課程與學習地圖

#### 大一：探索與基礎

課程：

- 人文學概論
- 人文地理學概論
- 文本分析與詮釋
- 數位人文方法與應用

學習行動：閱讀、理解、分析、表達、接觸數位方法。

可能成果：閱讀分析、文本詮釋、初步數位練習。

#### 大二：方法與議題

課程：

- 田野調查與質性研究
- 人文議題探索與設計
- 敘事學：從理論到應用

學習行動：調查、訪談、分析、敘事、轉譯。

可能成果：田野紀錄、訪談資料、議題分析、故事企劃。

#### 大三：跨域設計與實作

課程：

- 人文創新設計專題
- 文學社會學與文化研究
- 現當代文學理論與實務
- 數位策展：理論與實務
- 實務實習

學習行動：設計、協作、策展、企劃、實習、場域實作。

可能成果：數位內容、展覽企劃、文化方案、實習成果。

#### 大四：成果整合與展現

課程：

- 畢業專題製作（一）
- 文化事業與管理概論
- 畢業專題製作（二）

學習行動：整合、製作、展演、表達、職涯轉化。

可能成果：畢業專題、作品集、成果展演、職涯提案。

### 7.5 代表性選修區

主圖建議選取約12門代表性選修，完整課程另頁呈現。

#### 數位創意與內容設計

- 新媒體傳播與實作
- 人文數據探勘與文本分析
- 數位人文應用與空間人文
- 互動敘事與遊戲企劃
- 人本AI產品提案與設計

#### 文化永續與社會應用

- 文化創意產業概論
- 地方創生與數位敘事
- 文化節慶與展演活動企劃
- 品牌設計與故事行銷
- 策展學：理論與實務

#### 共用的內容與表達能力

- 語文修辭與溝通表達
- 報導文學與非虛構寫作

以上課程仍須以正式課程清單與實際開課狀況核定。

### 7.6 課程詳情卡

課程卡第一層顯示：課名、必修／選修、一句課程功能、方向文字標籤；年級由所在區塊標明。不得將全部資料直接堆在卡片上。

詳情面板顯示：課名、年級、必選修、課程功能、學習行動、方向、模組、可能成果與相關後續課程，並提供「加入／移出我的探索清單」。

「1＋3」模組只出現在詳情或進階說明。相關後續課程表示學習關聯，未經正式核定不得標為先修條件；未核定選修年級須標示「年級待確認」，不可自行安排。

### 7.7 興趣探索與我的探索清單

興趣選項：數位內容、AI與資料、地方文化、寫作創作、策展活動、品牌與故事行銷。

#### 地圖連動規則

- 預設不選興趣，顯示完整主地圖；可選一個或多個，建議先試兩至三個，不設完成門檻。
- 選取後即時強調符合任一所選興趣的課程，使用文字或圖示說明對應興趣。
- 非符合課程仍可讀、可操作；共同必修始終清楚可見，不以低對比淡化必要資訊。
- 方向控制預設為「全部」，選方向只強調相關課程；方向與興趣同時選取時，分別標明符合方向、符合興趣，避免隱藏課程或形成無結果的交集。
- 顯示選取摘要、相關課程數與「清除選擇」。無對應時顯示說明與重設操作，完整地圖仍保留。
- 可在同一地圖自行收藏課程；清單依年級整理，能返回課程位置，移除收藏不改動興趣。
- 清除興趣／方向與清空收藏是不同操作，按鈕名稱須明確。

#### 限制

不判定人格、適系或職業，不使用固定分流語言，不宣稱為正式修課建議。興趣與課程對應須由系所核實，不以課名關鍵字自動推定。

### 7.8 作品與學生故事區

每個案例應回答：

1. 學生原本對什麼有興趣？
2. 在系上做了什麼？
3. 最後形成什麼作品或能力？

優先使用真實資料：

- 課堂作品
- 畢業專題
- 田野紀錄
- 數位內容
- 策展成果
- 實習成果
- 學生訪談

## 8. 互動設計與心理學框架

心理學只用於改善探索與理解，不用於操控或製造焦慮。

| 心理機制 | 設計應用 | 必要限制 |
|---|---|---|
| 自我參照效應 | 從「你想做什麼？」開始 | 不把學生興趣固定成類型 |
| 自我決定理論 | 讓學生自行選擇興趣與查看內容 | 同時呈現必要的課程結構 |
| 心理所有權 | 自行建立「我的探索清單」 | 不將探索結果當成正式分流 |
| 能力感 | 呈現大一至大四逐步累積 | 不把學習簡化成遊戲積分 |
| 可能自我 | 展示四年後可能完成的作品 | 必須以真實課程與作品為依據 |
| 社會認同 | 呈現不同類型學生與作品 | 避免只展示少數明星成果 |
| 認知流暢性 | 短句、分層、手機優先 | 不犧牲課程資訊的完整性 |
| 敘事沉浸 | 讓使用者沿著學習旅程探索 | 不用過度戲劇化取代真實資訊 |

## 9. 使用者流程

### 流程A：快速瀏覽

首頁具體說明 → 四年學習總覽與兩大方向 → 自選查看課程或真實作品。

### 流程B：興趣探索

「開始探索」 → 地圖興趣控制區 → 選取任意興趣 → 同一四年地圖即時強調相關課程 → 查看詳情與作品／自行收藏。任何時候都可清除選擇查看完整地圖。

### 流程C：直接查課程

「直接看四年課程地圖」 → 四年總覽 → 展開年級 → 查看必修與代表性選修 → 開啟詳情 → 關閉後回到原課程。

### 流程D：查看作品

作品與故事 → 查看學習過程及對應課程 → 返回地圖並定位該課程；保留既有興趣與收藏，若該年級未展開則自動展開。

## 10. 響應式介面與互動規格

### 10.1 手機版

先顯示四年階段與簡短能力摘要，再依年級垂直展開課程，不要求橫向拖曳才能理解四年進程。允許多個年級同時展開，以便比較；預設展開大一，其餘摘要可直接操作。

興趣與方向控制放在地圖上方，可收合但保留已選摘要。詳情採底部面板或全螢幕對話框，長內容在面板內捲動，提供可見關閉按鈕，不能只靠滑動關閉。

### 10.2 平板與桌機

平板以可讀性決定兩欄或垂直年級排列；桌機空間足夠時使用四個年級欄。資料與互動規則一致，不以桌機布局縮小替代手機設計。桌機詳情可採側邊面板。

### 10.3 操作與狀態

- 頁面錨點、作品跳轉、詳情開關保留興趣、方向、收藏及年級展開狀態。
- 關閉詳情恢復原捲動位置，鍵盤焦點回到觸發課程卡；面板開啟時焦點留在面板，支援Escape關閉。
- 不依賴懸停；主要觸控區至少44×44 CSS像素，具可見鍵盤焦點。
- 從地圖到課程詳情不超過兩次操作，沒有登入或強制測驗。
- 狀態預設僅保留於本次開啟頁面；重新整理可重設。跨重新整理收藏須另決定是否啟用localStorage，遵循12.3。
- 顏色之外必須有文字／圖示標籤；非強調課程仍須維持可讀對比。
- 尊重減少動態效果設定，不用大幅動畫或自動跳動打斷閱讀。

### 10.4 視覺方向與待測方案

以淺色背景、清楚字級與留白呈現課程，兩方向使用有限的輔助色與文字標籤。深綠與深灰為候選基調，須與校系識別確認；真實作品與照片優先。首頁標題、色彩與固定底部導覽列不是已驗證決策，需透過原型測試定稿。

## 12. 技術規格與校內部署評估

### 12.1 建議技術組合

| 項目 | 技術 | 用途 |
|---|---|---|
| 網頁標準 | HTML5 | 頁面內容結構與語意標記 |
| 樣式 | CSS3 | 版面、字體、色彩、動畫與手機／平板／桌機響應式設計 |
| 程式語言 | TypeScript | 撰寫互動功能與課程資料型別；建置時轉換為瀏覽器可執行的 JavaScript |
| 前端介面 | React | 建立課程卡、年級展開、興趣篩選、路徑高亮與詳情面板 |
| 建置工具 | Vite | 在開發環境建置、打包並輸出靜態網站檔案 |
| 課程資料 | JSON | 管理課名、年級、必選修、方向、課程功能、能力與成果標籤 |
| 使用者暫存 | 瀏覽器端狀態；需要跨頁或重新整理保留時才使用 localStorage | 保存使用者自行勾選的興趣或課程，不收集身分資料 |

React的元件與事件處理適合實作本網站的課程卡片、篩選及畫面更新；Vite可將專案建置為可由靜態網站服務的檔案，預設輸出目錄為 `dist`。[React官方教學](https://react.dev/learn)與[Vite靜態部署及正式建置文件](https://vite.dev/guide/static-deploy)說明，React可用元件處理畫面、資料與事件，Vite則能建置供靜態網站服務的檔案。

### 12.2 正式環境部署型態

網站採「建置後靜態部署」：

1. 開發或校方核准的建置環境安裝 Node.js 與 npm，執行網站建置。
2. 建置工具產生 `dist/` 靜態檔案目錄。
3. 將 `dist/` 內的 HTML、CSS、JavaScript、JSON、字型與圖片部署至校方提供的網站目錄。
4. 對外使用校方核准的 HTTPS 網域或子目錄提供瀏覽。

正式主機只需提供靜態檔案服務。正式環境不需安裝 Node.js，不需執行 React、Vite 或應用程式伺服器，也不需資料庫或後端API。Vite官方文件說明，正式建置輸出可由靜態網站服務提供；若部署於校方網域的子目錄，需設定正確的公開路徑。[Vite正式建置文件](https://vite.dev/guide/build)

### 12.3 執行環境與資料流

- 網站互動在使用者的手機、平板或電腦瀏覽器執行。
- 課程資料隨網站檔案部署，以JSON提供，第一版不連接校務資料庫。
- 使用者選擇的興趣與課程只在瀏覽器端處理。
- 第一版不傳送使用者選擇至外部服務，不要求登入，不收集姓名、電子郵件或其他身分資料。
- 不依賴第三方CDN、外部字型服務或外部API；所需素材隨網站部署，降低校內網路與資安審查的變數。
- 若啟用localStorage，只保存使用者主動加入的興趣或課程代碼，並提供清除功能；校方可要求第一版改採僅限當次瀏覽的記憶體狀態。

### 12.4 校內主機需求

請資訊單位確認：

1. 是否能提供校內公開網站目錄，或系所網站中的指定子目錄。
2. 主機是否可提供一般靜態檔案：`.html`、`.css`、`.js`、`.json`、圖片與字型。
3. 是否支援 HTTPS，以及由哪個單位管理網域、憑證與續期。
4. 網站是否必須放在固定子路徑；若是，需提供完整路徑供建置設定使用。
5. 是否有單檔大小、總容量、檔案格式或上傳方式限制。
6. 是否要求使用校內Git、CI/CD或人工審核後部署。
7. 是否有內容安全政策（CSP）、快取、網站日誌或弱點掃描規範。
8. 是否可部署自行編譯的前端檔案，以及網站更新、備份與回復流程。

### 12.5 第一版不使用的服務

- Node.js正式伺服器
- 後端API
- 資料庫
- 使用者帳號與登入
- 個資蒐集
- 正式選課或學分試算
- 雲端函式或第三方代管服務
- 未經校方核准的分析追蹤程式

### 12.6 部署技術備註

本案第一版採單頁式探索介面，使用頁面內錨點、展開區塊與篩選狀態，不依賴多頁路由，因此一般靜態網站主機即可提供。若校方要求每個內容頁面都輸出獨立HTML、或要求伺服器端預先產生搜尋引擎內容，可另行評估Next.js靜態匯出；該作法同樣可輸出HTML、CSS與JavaScript檔案供靜態主機部署，但會增加框架與建置設定。[Next.js靜態匯出文件](https://nextjs.org/docs/app/guides/static-exports)

### 12.7 維運責任建議

- 系所負責課程名稱、學習說明、方向標記、成果與學生作品內容的正確性。
- 資訊單位負責確認主機、HTTPS、部署路徑、存取權限與校內資安規範。
- 每次課程資料更新後重新建置靜態檔案，再依校方流程發布。
- 課程資料應以正式課程清單為單一來源，並保留版本日期。

## 14. 使用者測試計畫

### 14.0 證據狀態

先前焦點團體討論是模擬高中生觀點，未實際招募或訪談學生。相關意見僅作設計假設，不得呈現為研究結論。第3節時間目標與第17節理解標準均待真實測試驗證。

### 14.1 測試對象

第一輪建議找8至12名高中二、三年級學生，包含：

- 傳統人文興趣型
- 不喜歡理科但未必喜歡人文型
- 探索型
- 數位內容與設計型
- 地方文化與社會議題型
- 務實與就業取向型
- 成績與志願受限型

### 14.2 測試任務

1. 看完首頁後，用一句話說明這個系在做什麼。
2. 找出大一會學什麼。
3. 找出一門自己感興趣的課。
4. 判斷兩大學習方向是否為固定分組。
5. 說明四年後可能完成的成果。
6. 選取與修改興趣，說明高亮課程與共同必修的差異。
7. 不選興趣直接找到課程；清除興趣後說明地圖是否完整。
8. 收藏兩門課，開啟詳情、關閉後返回原位置，再從作品回到課程。
9. 在手機上比較兩個年級，確認固定導覽未遮住內容。
10. 指出哪個地方讓他覺得這個系可能適合自己。

記錄任務成功與否、耗時、誤解、返回位置是否失落及原話。首頁文案與手機導覽方案可分開測試；小樣本用來發現問題，不推論全體高中生比例。不向學生展示上述類型標籤。

### 14.3 不使用的問法

避免只問：

> 你喜不喜歡這個網站？

應改問：

> 你看完後，覺得這個系最主要在做什麼？

因為「喜不喜歡」不能證明使用者真的理解網站內容。

## 15. 風險與因應

| 風險 | 說明 | 因應方式 |
|---|---|---|
| 太像傳統文科 | 人文語言過早、過抽象 | 首頁先呈現行動、作品與應用 |
| 太像一般文創系 | 只強調數位與創意 | 保留文學、語文與文化核心 |
| 太自由而失去方向 | 學生看不懂如何選擇 | 同時呈現共同必修與四年進程 |
| 太像心理測驗 | 個人路徑取代正式地圖 | 明確區分探索結果與課程結構 |
| 作品過度美化 | 學生不相信自己做得到 | 展示不同程度、真實課程成果 |
| 路徑名稱抽象 | 尤其是文化永續與社會應用 | 正式名稱搭配白話副標 |
| 課程資料不一致 | 網站與正式課表衝突 | 建立單一課程資料來源 |
| 資訊太多 | 手機使用者容易離開 | 分層呈現，先摘要後詳情 |

## 17. 驗收標準

網站完成後，至少必須符合以下標準：

- 高中生在10秒內能大致說明本系不是傳統單一文科。
- 高中生能在30秒內找到四年課程地圖。
- 使用者能清楚分辨必修與選修。
- 使用者能理解兩大方向不是固定招生分組。
- 使用者能找到自己感興趣的課程。
- 使用者能看見課程與成果的關係。
- 使用者不必登入即可完成探索。
- 手機版不需要橫向縮放即可使用。
- 興趣探索與直接瀏覽使用同一份地圖，沒有強制興趣選擇。
- 選取或清除興趣後，共同必修與四年結構仍清楚可見。
- 清除興趣不清空收藏；關閉詳情、從作品返回時保留狀態與定位。
- 手機年級可展開比較，面板可明確關閉，導覽不遮擋內容。
- 鍵盤可操作興趣、課程與詳情，焦點可見並可返回觸發位置。
- 模擬訪談與待測視覺不被描述為已驗證成果。
- 所有課程名稱、分類與敘述均能回到正式課程資料來源。

## 18. 最終產品原則

本網站的最終使用者經驗應該是：

> **我想做什麼？**
>
> **這個系有哪些方向？**
>
> **四年會如何逐步學習？**
>
> **我可以選哪些課程？**
>
> **我可能完成什麼作品？**
>
> **這裡是否有適合我的位置？**

最終目標不是讓學生被網站告知「你適合來我們系」，而是讓學生在探索後自己形成判斷：

> **我可以在這裡探索，而且我可能真的做得出一些東西。**
