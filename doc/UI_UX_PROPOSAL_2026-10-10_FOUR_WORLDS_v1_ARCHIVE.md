# 互動課程地圖提案｜四個領域，一條看得懂的學習路徑

日期：2026-10-10。版本：討論稿 v1。正式專案：`E:\DEV\leearning-map`。

本文件承接本次訪談，提出資訊架構、視覺與互動方向，供確認後再拆分開發任務。這不是已完成的介面，也不是正式課程或能力核定文件。本輪只新增本提案，沒有修改網站、課程資料、既有收藏、星座作品或遠端。

## 1. 提案主張與範圍

**用四個明亮的插畫場景吸引探索，用四年安排解釋課程，用目標與能力讓安排有意義。**

產品仍是一個功能性的課程地圖。學生不收藏、不看角色、不閱讀長篇故事，也應該能了解四大領域、找到全部課程、看懂年級安排與課程作用。

「四域探索圖鑑」可作為內部工作名稱；前台主標題保留「課程地圖」，避免使用者不知道這個網站是做什麼的。

### 訪談已確認的條件

- 使用者主要以自己的手機或電腦瀏覽，手機是優先設計情境。
- 四大領域一開始全部看見；拖曳／滑動只切換焦點與簡介，再點明確入口深入。
- 圖像採插畫場景，以環境與物件為主，整體明亮、有活力、有憧憬。
- 進入領域後以上下滑動為主要探索方式，畫面安定、內容自然進場、少量物件動態。
- 先理解領域的內容與目標，再看課程如何組成，以及想培養的能力。
- 四年安排與學習意義並存；每門課以一至兩個主要能力指標協助解讀。
- 收藏是自願支線。先探索，再主動揭曉探索角色，也能看其他角色。
- 角色具有想像力與樂趣；現實的能力及專業方向作為附註，不再要求星座形式。

以下的色票、場景名稱、版面細節、動效時間與角色示例都是設計建議，尚未視為使用者核准定案。

### 控制規模

本案包含：四領域入口、四年課程地圖、搜尋與全部課程、課程詳情、選用收藏與角色結果。

不新增：學系形象長頁、案例庫、作品展館、招生表單、多人世界、自由走動、3D 遊戲、闖關任務、排行榜或登入系統。既有命名／下載等功能另做相容性盤點，不在本提案擴充。

## 4. 視覺方向：晴日裡的四個探索場景

### 構圖與畫風

採有空間感的平面／輕透視插畫：清楚的形體、有限的材質細節、柔和日光、明確物件輪廓，使用少量飽和色作焦點。畫面有新鮮感與創作氣息，適合高中生觀看，不走童書幼齡比例或抽象陶瓷雕塑風格。

四個場景像同一幅探索圖的四個窗口，而不是四張格式完全相同、只有顏色不同的資訊卡。場景物件具有課程線索；課程內容仍由可讀的文字與標準操作承載。

- 圖像與課名不爭搶：文字放在穩定的閱讀表面，不直接壓在複雜插畫上。
- 領域切換時，色彩、選中輪廓與簡介一起更新，不改變控制位置。
- 不用星點、粒子或金色連線作為全站預設語言。
- 整站明亮，但控制與文字有足夠深色對比；不是把所有元素調成低對比粉彩。
- 角色圖片可以有完整人物造型；這與四大領域「環境／物件為主」是不同層級。

| 人文識別   | `#8C79C6` | 紫色插畫重點與小面積分類標記       |
| 敘事識別   | `#E69B5F` | 暖橘創作物件與小面積分類標記       |

純色對比本輪量測：主要文字／暖白 11.48:1，次要文字／暖白 5.80:1，主要文字／白色 12.63:1，次要文字／白色 6.38:1，白字／行動色 7.70:1，行動色／暖白 7.00:1。

這只驗證指定純色組合，不等於整頁已通過可及性。四種領域色不是通用文字背景：例如主要文字／紫色 3.41:1、主要文字／天藍 4.27:1，不適合作一般小字閱讀組合。分類文字優先放在白／暖白表面；插畫合成、邊界、焦點與 disabled 狀態另行量測。

### 字體與尺度

繁體中文以現有清楚的系統字／回退字型為主，暫不為提案新增外部字型依賴。內文 16–18 CSS px、行高約 1.6；資訊標記以 14 px 為起點，重要課名不縮成小字。

使用 4／8／12／16／24／32 px 共用間距；手機約 16 px 左右留白。互動命中區以至少 44×44 CSS px 為設計目標，與鄰近按鈕分離。200% 文字與窄螢幕時允許自然增高，不為塞滿首屏而裁切。

### 素材的最小製作方式

先完成一個領域樣張，建議數位人文，確認色彩、構圖、文字共存與手機裁切後，才擴展至四張。

- 同一張領域母圖用於入口局部與領域頁，不另生一套背景。
- 首版母圖加少量可分離物件即可；若要動態，另提供相應透明圖層，不要求程式猜測平面圖中物件的位置與遮擋。
- 手機與桌機共用畫風，依重點構圖輸出不同裁切；領域標題、數量與按鈕都由網頁渲染，不寫進圖片。
- 先做一個探索角色的風格樣張。其餘角色數量由課程組合與素材負擔決定，不預先要求十二個。
- 圖片失敗或尚未完成時，以靜態形狀與完整文字降級，所有課程仍可達。
- 原始圖保留；後續另製 WebP／AVIF 與適尺寸版本，不覆寫原 PNG。

已有的深藍底景、四張抽象雕塑與四張星座圖卡均保留。星座圖卡存於 `public/images/area-cards/`，此次可作歷史參考，不要求沿用為新版插畫，也不在提案階段刪除。

一個年級課程較多時，沿用可辨認的分段／分頁控制，手機先以每段最多 6 門為待測起點，明示本年總數及目前位置，不逐門無限追加。桌機起點為每段 12 門。這是資訊量控制，不是固定高度截斷內容。

### C. 課程詳情：事實、意義、選用收藏

手機用既有可關閉的詳情抽屜作基礎，順序如下：

1. 完整課名、領域、年級／學期、必選修與學分。
2. 一句「這門課在學什麼」及其在領域中的作用，須核定後呈現。
3. 一至兩個主要能力指標，以「練習做什麼」描述，不展示研究文件長篇評分規準。
4. 有根據的相關課程；標示「延伸探索」，不冒充先修。
5. 次要操作「加入我的課程／已加入」，說明「記下感興趣的課程，並非正式選課」。

詳情提供可見關閉鈕、Escape、焦點管理與背景隔離。收藏按鈕與課程詳情入口是分開的命中區，不因點課程就自動加入。返回原課程，不丟閱讀位置。

## 7. 桌機低保真：增加比較能力

課程詳情在容得下完整內容時使用側欄，或縮減地圖欄位寬度後仍維持可讀布局；容不下四欄加側欄時改為對話框，不把 1024 px 當成「一定夠寬」。四欄不各自形成狹窄、長距離的內部捲動區，避免滑鼠／觸控板不知正在捲哪一段。

領域色、年級、收藏與能力是不同語意。點選課程後才突出必要的相關項目，不先畫滿跨欄線條。

## 8. 代表性互動與動效契約

以下時間是原型起點，不是已量測的流暢性保證。資料與導航立即更新，不等待動畫才完成操作。

| 操作           | 回饋與成功狀態                                                      | 反向／取消與替代方式                                                                |
| -------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 聚焦領域       | tap／按鈕立即改文字與選中標記；滑動有短距離跟手，約 160–220 ms 吸附 | 未達門檻回原焦點；邊界不換頁；鍵盤與上一／下一按鈕可完成；reduced-motion 直接換輪廓 |
| 進入／返回領域 | 明確按鈕觸發，約 180–240 ms 局部交接；標題與範圍同步更新            | Back 恢復入口焦點或前一課程範圍；快速反向不排動畫佇列；減少動效直接交接             |
| 年級展開／收合 | 範圍與課程數即時明確，短距離自然展開                                | 可切其他年級；保留年級標題位置；原生按鈕與 `aria-expanded`；減少動效不插值高度      |
| 查看／關閉詳情 | 桌機側欄或手機抽屜，約 180–240 ms 交接                              | 可見關閉鈕、Escape／Back 與焦點恢復；可立刻取消；減少動效直接顯示                   |
| 加入／移除收藏 | 勾選／文字與計數即時更新，約 80–120 ms 局部按壓回饋                 | 同按鈕可移除，沿用既有復原；清篩選不清收藏；不要求拖曳，也不播放每次慶祝            |
| 主動揭曉角色   | 約 300–450 ms 插畫、稱號與依據交接，結果可立即閱讀                  | 可略過、回收藏或繼續探索；減少動效直接顯示；不播放不可略過影片                      |

閱讀中的插畫物件最多少量局部微動，可在進入可視區時一次呈現。例如字塊對齊、地圖標記亮起；不使用持續全場旋轉、鏡頭推進、捲動鎖定或陀螺儀。

動效以局部 opacity／transform 為主；離開畫面或頁面隱藏時停止，尊重 reduced-motion。靜態畫面必須能完成所有理解與操作。

## 9. 探索角色：記住選擇，也看懂選擇

主流程：**探索 → 自願收藏 → 在我的課程主動揭曉 → 看依據 → 看其他角色或繼續探索。**

入口可以有一句低強度預告「你的探索，會形成什麼角色？」；不展示大型空角色、缺幾門、待解鎖或完成百分比。沒有收藏仍可從我的課程的次要入口看角色圖鑑；不因支線存在而讓空收藏阻擋主站。

### 一張角色結果的三層內容

1. **想像層**：角色插畫、稱號與一小段故事。
2. **依據層**：哪些實際收藏形成這個探索方向、涉及哪些想發展的能力。
3. **現實附註**：可探索的專業方向，不寫職業資格、適性判定或能力達成保證。

示例「記憶修補師」：想像上找回散落的故事；現實附註可探索文化研究、數位典藏或策展。這只是角色架構示意，不是已完成的能力／課程對照，也不限制所有角色都走人文懷舊題材。

### 配對與圖鑑的設計邊界

- 角色根據已審核的課程／能力對照解釋選擇，不單靠課名推測人格。演算法與角色類別尚待設計，不直接沿用星座性格權重。
- 可用簡單、版本化、可說明的相似度；相同收藏與規則版本得到穩定結果，不需要執行期 AI 或每次載入隨機換角色。
- 跨域選擇也是有效組合，不強迫每個人只屬於一個領域。角色不等於四大領域重新分類。
- 不要求集滿、四年均勾選或指定課程才能查看。有少量收藏可提供暫定探索方向；不足以區分時誠實標示「目前可探索的方向」，不要製造精確分數或稀有度。
- 結果依據只引用實際收藏。圖鑑的示例組合不自動加入；點其他角色也不換掉原收藏。
- 同門課可關聯不同角色，角色內以 ID 去重。關聯課程按真實四年分布呈現，不為湊人數／年級改正式資料。
- 收藏改變後提示結果可更新，由使用者主動查看；不在每次增刪課程後跳出角色。
- 自選欣賞其他角色時，標明「正在查看其他角色」，不冒充是由自己的收藏配對而來。
- 舊星座資料、命名、匯出與作品先盤點相容性；不自動轉換成新角色、覆蓋或刪除。新舊結果不建立第二份課程收藏。

## 10. 能力與文案的後續整理方式

前台「一至兩個主要能力指標」是閱讀強度，不是宣稱每門課只涉及兩種能力。後台可保留更多原始對照與研究依據；不用全擠進課程列表。

後續資料工作建議順序：

1. 以本系四大領域、69 門課程與可取得的大綱界定學習內容。
2. 從 accepted 訪談條目找對應的定義、可觀察行為及情境，檢查 AI 草稿與訪談佐證是否相符。
3. 收斂為適合本系、學生讀得懂的新類別，類別數量由差異與可解釋性決定。
4. 逐課提主要一至兩項對照，記錄來源 ID、依據、信心／限制及審閱狀態；證據不足的課保留待確認。
5. 內容負責人確認後才對外呈現，再據此建立角色組合與解釋文案。

能力分類、逐課摘要與角色對照維持獨立映射，不覆寫原始課程核定欄位。新映射至少記錄 course ID、capability ID、來源 metadata IDs、依據摘要、版本、draft／reviewed 狀態與審閱者；研究 ID 與業者訪談原文不需公開出現在網站。

研究 JSON 不整包複製到 public、不讓前台載入 18.5 MB 訪談資料。僅輸出經審核、最小必要的公開描述與課程對照，排除業者身分、私密情境與原始引言。亦不將既有全校 1,169 門課程判讀當成本系已核定對照。

## 11. 風險與驗證計畫

本提案來自利害關係人訪談與現有資料核對，不是高中生實測結論。網站原有工程測試的通過，也不代表新方案已好用或美觀。

### 原型先驗證三件事

1. **入口理解**：學生看得出四個領域，知道滑動是比較、按探索才進入；不依賴操作說明才能找到按鈕。
2. **課程理解**：不收藏也能找到指定課程，看懂年級／學期／必選修，並用自己的話說出領域與幾門課的學習關聯。
3. **支線理解**：願意收藏的人知道何時揭曉、角色從何而來；不收藏的人不覺得缺少必要步驟。

建議先以約 5–8 位高中生做形成性試用，包含不同熟悉程度的使用者；這是找問題的小樣本，不用來宣稱統計代表性。另做鍵盤、讀屏與減少動效走查，若無法取得對應使用者或裝置，明列未驗證項。

測試任務包括：找全系大二必修、找到一門跨領域課並返回、解釋一個領域的目標與兩門課的關係、辨識收藏與正式選課的差別、主動查看其他角色而不改掉收藏。先記錄完成、誤解與迷路點，不以停留越久當成成功。

### 工程與素材驗收起點

- 遍歷 69 個唯一 ID，與四領域／四年／必選修計數一致；無分類或待審能力不能導致課程消失。
- 320／390／768／1024／1440 CSS px、低高度、橫向、200% 文字與瀏覽器 zoom 皆可讀、可達。
- 用「古典文獻的數據化與文化IP轉譯」等真實長課名驗證換行、詳情與收藏布局。
- 全鍵盤、焦點還原、Back／Escape、觸控斜向手勢、快速反向及 reduced-motion 可完成相同主任務。
- 圖片失敗、慢速載入與儲存失敗可繼續找課，不能聲稱已永久保存但實際未成功。
- 配色在真實圖像、所有控制狀態中量測；本文純色數字不是整頁 WCAG 認證。
- 首屏四個領域縮圖的傳輸量合計先以約 300 KB 為待測預算；不先載入所有高清角色與場景原圖。必要素材分尺寸、延後非首屏載入，不新增重型 3D 依賴。
- 在實際手機測手勢與捲動，建立同環境載入／操作基準；沒有實機證據前不宣稱已流暢。
