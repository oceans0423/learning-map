## 1. 產品摘要

本產品是一個面向高中生的「互動式四年課程與學習地圖」。它不是完整學系網站，也不是選課、排課或能力評量系統。

使用者應能在短時間內理解：

1. 四年各階段主要學什麼。
2. 文學文化與人文方法如何形成共同基礎。
3. 課程如何延伸至三個應用探索面向。
4. 哪些課程屬於必修、選修，以及安排在哪個年級與學期。
5. 專題、實習與畢業製作如何整合四年的學習。

核心敘事：

> 從文學文化與人文方法出發，透過敘事創作、數位媒介及文化社會實踐，把所學轉化為作品、企劃與行動。

## 2. 目標與範圍

### 2.1 核心目標

- 讓高中生不必理解系所術語，也能看懂四年學習進程。
- 將 69 門大學部課程整理成容易閱讀、探索與比較的課程地圖。
- 清楚呈現共同基底、應用探索與整合成果之間的關係。
- 以精緻視覺與必要互動，建立可信且具辨識度的對外介面。
- 手機不需橫向拖曳或縮放即可理解內容。

### 2.2 第一版不做

- 正式選課、排課、衝堂檢查、學分試算、畢業資格與先修判定。
- 人格測驗、適系測驗、興趣測驗或自動推薦。
- 能力分數、逐課能力標註與能力檢視（第二階段）。
- 示例路徑（第二階段）。
- 收藏清單、Cookie、localStorage、帳號與跨裝置同步。
- 學生作品案例系統。
- 系所沿革、師資、職涯、招生 FAQ 或家長專區。
- 使用者測試與任何個資蒐集。
- 後端伺服器、資料庫或 API。

## 4. 課程模型

### 4.1 課程範圍

依正式課程清單，大學部共 **69 門**：

| 項目 | 數量 |
|---|---|
| 必修 | 15 門，每門 2 學分，共 30 學分 |
| 選修 | 54 門，每門 2 學分 |

各學期門數：

| 一上 | 一下 | 二上 | 二下 | 三上 | 三下 | 四上 | 四下 |
|---|---|---|---|---|---|---|---|
| 6 | 6 | 11 | 12 | 11 | 12 | 7 | 4 |

- 碩士班課程不納入本地圖。
- 學分與必選修一律以課程清單為準，不引用其他文件的模組學分數。

### 4.2 三層學習結構

#### 第一層：共同基底

以文學文化與人文方法為共同基礎，涵蓋文本閱讀、文化理解、敘事表達、田野調查、研究方法及批判思考。

**「作用」與「必選修」是兩個獨立屬性。** 共同基底不等於全部必修：必修中也有應用課（如數位人文方法與應用、數位策展：理論與實務）與整合課（如人文創新設計專題、實務實習、畢業專題製作）。

#### 第二層：應用探索

第一版採用以下三個探索面向。面向不代表招生分組、固定分流或正式選課建議，同一門課可連結多個面向。

| 面向 | 涵蓋內容 |
|---|---|
| **敘事與創作** | 散文、小說、詩歌、報導、文案、出版及跨媒介敘事 |
| **數位人文與媒介** | 數位敘事、資料方法、AI 協作、互動媒介、空間人文及數位策展 |
| **文化與社會實踐** | 地方創生、田野調查、文化資產、策展、品牌、節慶及社會議題實作 |

- 面向名稱集中於單一設定檔，日後若調整可一次替換。
- 本系不設「語文教育」面向。偏教學／語言學的課程仍完整保留於地圖，`primaryTrack` 為 `null`。

#### 第三層：整合成果

透過專題、實習、策展、企劃及畢業製作，整合共同基底與不同面向的學習。

### 4.3 四年學習主線

> 探索與奠基 → 方法與表達 → 跨域實作 → 整合與展現

| 年級 | 學習重點 | 培養的能力 | 可能進行的學習活動 |
|---|---|---|---|
| 大一 | 建立人文、文本、文化與數位方法基礎 | 閱讀理解、文本分析、基礎表達、數位工具入門 | 閱讀分析、文化觀察、基礎表達與數位練習 |
| 大二 | 學習田野、研究、敘事及議題分析方法 | 田野研究、資料整理、敘事轉譯、議題分析 | 訪談、資料整理、故事企劃與議題分析 |
| 大三 | 進入專題、策展、實習及進階選修 | 企劃協作、媒介應用、策展與場域實作 | 數位內容、創作、文化方案、策展與場域實作 |
| 大四 | 統整所學並完成公開成果 | 綜合運用、專案完成、公開表達 | 畢業專題、作品集、成果展演或文化提案 |

- 此表為年級層級摘要，不是逐課能力標註，也不取代課程大綱。
- 上線前由系所走查文字。

## 6. 互動規格

互動只服務一個目的：協助使用者理解課程及其在四年中的位置。

### 6.1 年級展開

- 四個年級各有「學什麼／如何學／培養什麼能力／可能完成什麼」摘要。
- **預設狀態：** 大一展開，其餘年級收合。桌機四年摘要同時可見；手機依序垂直排列。
- 每個年級內，**必修直接顯示**；選修收合並標示「選修（共 N 門）」，點擊展開。
- 選修順序依課程清單排列，不暗示優先或推薦。
- 年級可同時展開多個。

### 6.2 學期切換

- 選項：「全年／上學期／下學期」，預設全年。
- 切換只改變可見課程，不改變頁面結構與年級展開狀態。

### 6.3 結構圖互動（強調模式）

結構圖本身就是控制介面，不另做一組面向按鈕。

**可點區：**

| 點擊 | 效果 |
|---|---|
| 共同基底 | 強調 `role = foundation` 的課程 |
| 敘事與創作／數位人文與媒介／文化與社會實踐 | 強調符合該面向的課程 |
| 整合成果 | 強調 `role = integration` 的課程 |

**強調，而非篩選：** 符合條件的課程加強顯示；其他課程保留在原位，降低視覺強度，但仍可讀、可點，且維持無障礙對比。

**面向符合規則：** 課程的 `primaryTrack` **或** `relatedTracks` 包含任一已選面向，即視為符合。`primaryTrack` 為 `null` 且無 `relatedTracks` 的課程不符合任何面向。第一版不區分主要與相關面向的強調強弱。

**組合邏輯：**

```
可見課程 = 符合目前學期的課程
強調課程 = 可見課程中，符合任一已選面向或作用條件者（OR）
```

- 五個可點區皆可複選，彼此為 OR。
- 年級展開狀態不參與強調。
- 未選任何條件時，所有課程正常顯示。

**狀態列：** 地圖上方顯示目前條件與結果，例如：

> 已強調 18 門相關課程，其他課程仍保留顯示。　［清除條件］

- 不寫「共 18 門課」，避免誤以為畫面只剩 18 門。
- 命中 0 門時顯示「已強調 0 門相關課程」，不視為錯誤。
- **「清除條件」只清除結構圖的選取**，不重設學期與年級展開。

**用語：** 程式命名、無障礙文字與介面文案一律用「強調」，不用「篩選」。不使用「推薦你」「你最適合」等判定語言。

### 6.4 課程卡

| 顯示 | 規則 |
|---|---|
| 課程名稱 | 必定顯示 |
| 必修／選修 | 必定顯示，作為主要標籤 |
| 學期、學分 | 必定顯示 |
| 作用（基底／應用／整合） | 必定顯示 |
| 主要面向 | `primaryTrack` 有值時顯示 |
| 相關面向 | 不在卡片顯示，只在詳情顯示 |

### 6.5 課程詳情

**所有課程卡一律可點**，以手機底部面板／全螢幕對話框、桌機側邊抽屜呈現，內容至少包括：

- 課名、年級、學期、學分、必修／選修。
- 作用，以及在四年中的位置說明。
- 主要面向與相關面向。
- 「實際開課依當學年度課表」提醒與官方課表連結。
- `summary`、`activities`、`possibleOutputs`：**僅在對應 `verification` 為 `approved` 時顯示**；否則不顯示該區塊，改為一行：

> 課程詳細說明整理中，實際內容請依當學年度課表及課程大綱為準。

關閉詳情後回到原捲動位置與強調狀態，焦點回到原課程卡。

### 6.6 網址狀態與返回鍵

- URL 查詢參數記錄：學期、結構圖選取、展開中的年級、開啟中的課程。
- 重新整理或分享網址可重建相同畫面。
- 切換學期、結構圖選取或年級展開時用 `replaceState`，不新增瀏覽紀錄。
- 開啟課程詳情時用 `pushState`，按返回鍵先關閉詳情。
- 網址不得含個人資料。

參數範例：

```
?sem=2&focus=foundation,narrative&open=1,2&course=course-010
```

**容錯規則**（實作於 `urlState.ts`，並列為單元測試）：

| 狀況 | 處理 |
|---|---|
| `sem` 無效 | 視為全年 |
| `focus` 含無效值 | 忽略無效值，保留有效值 |
| `open` 無效或空 | 回到預設（大一展開） |
| `course` 找不到 | 不開啟詳情 |
| 參數有重複值 | 自動去重 |

## 7. 視覺與操作原則

### 7.1 視覺方向

- 人文氣質、當代感與學術可信度，避免制式校務系統風格。
- 年級是主要閱讀軸，面向是輔助辨識軸。
- 三層結構層次清楚，但不可讓人誤認為固定分流。
- 卡片簡潔，詳細內容在使用者主動開啟後才出現。
- 不做需要縮放、拖曳或辨認大量連線的節點圖。

### 7.2 響應式

| 裝置 | 版面 |
|---|---|
| 手機 | 單欄垂直、年級手風琴；結構圖可收合或固定於易操作位置 |
| 平板 | 一至二欄，保持年級順序 |
| 桌機 | 四欄或寬版時間軸，不犧牲文字可讀性 |

### 7.3 動效

- 展開、強調與詳情切換使用輕量動畫。
- 動效不延遲主要操作，並尊重系統「減少動態效果」設定。

### 7.4 無障礙

- 所有功能可用鍵盤完成，焦點樣式清楚。
- 詳情開啟時焦點鎖在面板內，支援 Escape 關閉。
- 顏色不是唯一辨識方式，狀態同時以文字、標籤或邊框表達。
- 被降低強度的課程仍符合文字對比標準。
- 觸控目標至少 44×44 CSS 像素。
- 按鈕、展開與選取狀態具正確語意標記（如 `aria-pressed`、`aria-expanded`）。

## 8. 課程資料規格

### 8.1 資料檔

- 路徑：`doc/course/courses_v1.json`，開發時複製到專案 `src/data/courses.json`，並納入版本控制。
- 內含 `meta`（系名、總數、面向與模組清單、定案說明、課名正規化說明、ID 政策）及 69 筆 `courses`。

### 8.2 單筆格式

```json
{
  "id": "course-010",
  "name": "地方創生與數位敘事",
  "sourceName": "地方創生與數位敘事",
  "year": 1,
  "semester": 2,
  "credits": 2,
  "type": "elective",
  "role": "application",
  "module": "數位人文",
  "primaryTrack": "文化與社會實踐",
  "relatedTracks": ["數位人文與媒介"],
  "subTags": [],
  "summary": null,
  "activities": [],
  "possibleOutputs": [],
  "offeringNote": "實際開課依當學年度課表",
  "sourceVersion": "115學年度",
  "verification": {
    "basic": "approved",
    "role": "approved",
    "tracks": "approved",
    "module": "approved",
    "summary": "draft",
    "activities": "draft",
    "possibleOutputs": "draft"
  }
}
```

### 8.3 欄位規則

| 欄位 | 規則 |
|---|---|
| `id` | **永久識別碼**。一經發布不得因排序、新增或刪除課程而重新編號；新增課程用下一個未用編號，刪除課程不回收編號 |
| `name` | 顯示用課名：CJK 相容表意字轉為標準字、全形英數轉半形，標點維持原樣 |
| `sourceName` | 課程清單的逐字原始課名，供追溯，前台不顯示 |
| `year`、`semester`、`credits`、`type` | 依課程清單；`type` 為 `required`／`elective` |
| `role` | `foundation`／`application`／`integration`，與 `type` 獨立 |
| `primaryTrack` | 三面向之一或 `null` |
| `relatedTracks` | 可多個，介面不得暗示固定路徑 |
| `module` | 計畫書模組（人文思維與方法、數位人文、文化創意與社會設計、文學創作），**前台不顯示** |
| `subTags` | 面向次標籤，預留擴充，**前台不顯示** |
| `summary`、`activities`、`possibleOutputs` | 可留空，`draft` 時前台不顯示 |
| `verification` | 分別記錄 `basic`、`role`、`tracks`（涵蓋 `primaryTrack` 與 `relatedTracks`）、`module`、`summary`、`activities`、`possibleOutputs`，值為 `approved`／`draft` |

### 8.4 定案狀態與顯示

| 欄位 | 狀態 | 依據 |
|---|---|---|
| 課名、年級、學期、學分、必選修（`basic`） | `approved` | 課程清單（最終版本） |
| 作用（`role`）、面向（`tracks`）、模組（`module`） | `approved` | 2026-10-08 由系所內容負責人定案，不另經課程委員會 |
| 課程說明、活動、產出 | `draft`（尚未撰寫） | 第一版前台不顯示，詳情改顯示「整理中」說明 |

- 課程與分類日後若有異動，由內容維護者直接更新 `courses_v1.json`，並重新產生 `courses_v1_overview.md`。
- 前台顯示規則一律依 `verification` 判斷，不寫死於元件；日後補上課程說明時，只需將對應欄位改為 `approved`。

### 8.5 分類統計

| 作用 | 門數 |
|---|---|
| 基底 | 20 |
| 應用 | 45 |
| 整合 | 4 |

| 主要面向 | 門數 |
|---|---|
| 敘事與創作 | 17 |
| 數位人文與媒介 | 10 |
| 文化與社會實踐 | 18 |
| 無（20 門基底＋4 門整合） | 24 |

全部 45 門應用課皆有主要面向；基底與整合課的主要面向皆為 `null`。單元測試應以此統計作為資料檢核基準。

## 9. 技術與部署

| 項目 | 決定 |
|---|---|
| 形態 | 獨立靜態站點，不嵌入既有校方 CMS |
| 框架 | React + Vite（SPA） |
| 語言 | TypeScript |
| 課程資料 | JSON，納入版本控制，建置時打包 |
| 狀態 | URL 查詢參數；元件狀態存在記憶體 |
| 儲存 | 不使用 Cookie、localStorage |
| 輸出 | `vite build` 產生靜態檔至 `dist/` |
| 部署 | 校方核准之 HTTPS 網域或子目錄；子目錄需設定 `base` 路徑 |
| 外部依賴 | 不使用第三方追蹤、外部 API；字型自帶或使用系統字型 |
| 瀏覽器 | 最近兩版的 Chrome、Edge、Safari、Firefox，以及 iOS Safari 與 Android Chrome |

**建議目錄：**

```
src/
  data/courses.json        課程資料
  config/tracks.ts         面向名稱與顏色設定（單一來源）
  lib/highlight.ts         強調邏輯（可見課程、強調課程）
  lib/urlState.ts          URL 讀寫與 replaceState / pushState
  components/              結構圖、年級區塊、課程卡、詳情面板、狀態列
```

`lib/highlight.ts` 應為純函式並撰寫單元測試，涵蓋 §6.3 的符合規則與組合邏輯。

## 12. 驗收標準

### 12.1 內容

- 69 門課程皆可對應課程清單，課名、年級、學期、學分、必選修正確。
- 必修 15 門、30 學分，與清單一致；全部 138 學分。
- 分類統計與 §8.5 一致。
- `verification` 為 `draft` 的內容不出現在前台。
- 頁尾顯示資料學年度與「實際開課依當學年度課表」。

### 12.2 理解（系所走查）

不操作任何控制，首頁即可看出：

- 四年學習的先後進程。
- 文學文化與人文方法是共同基礎。
- 三個探索面向不是固定分組。
- 專題、實習、畢業製作具整合作用。
- 必修與選修的差異。

### 12.3 互動

- 大一與必修預設可見，選修可展開收合。
- 學期切換結果正確，且不影響年級展開。
- 結構圖五區可單選、複選，結果符合 §6.3 規則；清除條件不重設學期與展開。
- 狀態列文字與實際強調門數一致。
- 每張課程卡都能開啟詳情，空內容顯示「整理中」說明。
- 重新整理或分享網址能重建畫面；返回鍵先關閉詳情。
- 手機不需橫向縮放即可完成所有操作。
- 鍵盤可完成所有操作。

### 12.4 品質

- `lib/highlight.ts`、`lib/urlState.ts`（含 §6.6 容錯規則）及資料檢核（§8.5 統計、ID 唯一）單元測試通過。
- 常見手機與桌機寬度無截斷、重疊或無法操作元件。
- 首屏載入快速，靜態資源經壓縮。
- HTTPS、錯誤頁、基本 SEO 與分享預覽設定完成。

## 15. 產品原則

1. 先讓人看懂，再提供更多功能。
2. 年級是主軸，面向是探索工具。
3. 共同基底不能被應用面向淹沒。
4. 不把面向呈現成固定分流。
5. 不把規劃課程寫成每年必然開設。
6. 沒有可靠資料時，少寫比推測更可信。
7. 互動必須幫助理解，不為互動而互動。
