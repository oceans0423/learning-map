## 0. 一頁摘要

本專案正在重新規劃，但核心仍是「讓使用者看懂 69 門課如何組成四年學習路徑」的互動式課程地圖，不是招生官網，也不是單純的角色蒐集遊戲。

新的記憶與探索機制是 **12 個預先定義的角色**：

- **4 個領域角色**：代表四大課程領域，負責入口、導覽與領域理解。
- **8 個專業角色**：代表跨領域的課程與能力組合，負責說明「這些學習最後能做出什麼」。
- 學生收藏課程後，系統依其實際收藏內容，產生最接近的 **1 個既定專業角色**；不是生成任意新角色。
- 學生可查看其餘 7 個專業角色、各自的能力、代表課程、四年形成方式與成果方向。

目前只完成角色系統的語意草案，**尚未核定 8 個專業角色、尚未完成 69 門課映射、尚未設計角色形象、尚未實作角色配對功能**。下一步不應直接生圖或寫匹配程式，而應先把 8 個專業角色的意義與界線定稿。

## 1. 為什麼重新規劃

先前版本曾探索星圖、十二星座、四世界插畫、旋轉星河入口等表現方式。過程中確認了幾個根本問題：

1. 69 門課若只以文字、SVG 或長列表呈現，資訊完整但缺乏記憶點。
2. 星座收藏有趣，但容易成為附加功能，與主要課程地圖形成兩套相互競爭的產品。
3. 大型世界觀、複雜入場動畫與過度遊戲化，會使功能性課程地圖變得龐大且難用。
4. 四大領域雖能協助分類，仍不足以說明跨領域課程能組成哪些實際能力與成果。
5. 高中生與行動裝置使用者需要先被吸引，但最終仍必須清楚回答：有哪些課、四年怎麼走、會培養什麼、能做出什麼。

因此，新方向保留原本「以有趣分類創造探索動機與記憶點」的邏輯，將星座改為角色系統，並讓角色直接建立在課程與能力資料之上。

## 2. 產品目標與非目標

### 2.1 產品目標

- 清楚呈現全部 69 門課的名稱、年級、學期、必選修、學分及領域歸屬。
- 幫助使用者理解四大領域各自在學什麼、培養什麼能力、形成什麼成果。
- 把跨課程的學習關係轉譯為 8 個容易記住的專業角色。
- 讓收藏行為產生可解釋的回饋，而不是只形成書籤清單。
- 讓學生看見「人文不只等於文學」，還包含數位、人本 AI、內容、策展、文化實踐與問題解決。
- 手機優先，並保留桌機上的完整課程比較與路徑閱讀能力。

### 2.2 非目標

- 不製作完整學系招生網站。
- 不建立龐大的 RPG、開放世界或角色養成遊戲。
- 不以角色取代完整課程地圖。
- 不做人格測驗，也不推論性格。
- 不保證職業資格、就業結果或能力認證。
- 不讓學生自行捏角色或畫角色。
- 不用隨機結果、假百分比或不可說明的 AI 黑箱配對。
- 現階段不需要課程大綱；新學系尚無完整大綱，應使用清楚、正向的介紹文字，不需防禦性強調資料邊界。

## 3. 12 個角色的兩層架構

### 3.1 四個領域角色

用途：課程地圖入口、領域導覽、領域認知。  
回答的問題：「這個領域如何學習與理解世界？」  
它們不是職業，也不是學生收藏後的配對結果。

2026-10-10 已確認的角色名稱：

| ID | 工作名稱 | 對應領域 | 核心意義 |
|---|---|---|---|
| `domain-inquirer` | 觀察家 | 人文思維與方法 | 觀察、閱讀、考證、提問與理解脈絡 |
| `domain-storymaker` | 說書人 | 敘事與內容創作 | 把經驗與觀點轉化為可傳達的故事與內容 |
| `domain-digital-translator` | 解碼師 | 數位人文 | 用資料、工具與互動形式重新理解及表達人文問題 |
| `domain-cultural-practitioner` | 設計師 | 文化創意與社會設計 | 將人文洞察轉化為企劃、場域行動與社會實踐 |

四個名稱代表理解世界的基礎方法，不是職業、人格分類或學生收藏後的配對結果。

### 3.2 八個專業角色

用途：跨領域理解、收藏配對、角色圖鑑與課程探索。  
回答的問題：「這些課程和能力組合起來，可以完成什麼？」  
八個角色不是四個領域各切兩個，而應允許跨域與課程重複出現。

2026-10-10 已確認的角色名稱：

| 編號 | 工作名稱 | 暫定專業意義 |
|---|---|---|
| P1 | 探索者 | 從問題意識、文本與田野資料建立可論證的理解 |
| P2 | 創作人 | 將知識、觀察與議題轉化為故事、影像或跨媒體內容 |
| P3 | 引路人 | 組織、編修、解釋並向不同受眾傳播複雜知識 |
| P4 | 分析師 | 整理與分析人文資料，辨識模式並提出可解釋的洞察 |
| P5 | 策展人 | 結合內容、數位媒介與使用者體驗，設計互動展示或策展 |
| P6 | 造物者 | 從人的需求、文化情境與倫理出發，設計 AI 應用或服務 |
| P7 | 策略師 | 將文化內容轉化為品牌敘事、活動、展覽與溝通企劃 |
| P8 | 開拓者 | 與場域及合作方共同辨識需求、提出方案並推動實踐 |

### 3.3 尚待核定的重疊問題

- P2「故事與內容製作」與 P3「編輯與知識傳播」界線是否足夠清楚？
- P5「互動體驗與數位策展」與 P7「文化品牌與策展企劃」是否過度重疊？
- 只有八個名額時，P1「人文研究者」是否應保留為獨立角色？
- 八個角色是否完整呈現學系最想被看見的實務與學術發展方向？

上述名稱已確認；專業語意界線、角色形象與課程權重仍須另行核定。

## 4. 每個角色必須具備的資料

12 個角色應共用一致的資料模型，至少包含：

1. `id`：穩定識別碼，不隨顯示名稱變動。
2. `version`：語意或映射規則版本。
3. `displayName`：對學生呈現的記憶型名稱。
4. `semanticName`：內部可精確審核的語意名稱。
5. `tagline`：一句話定位。
6. `coreQuestion`：此角色持續處理的核心問題。
7. `coreAbilityIds`：約 3 個核心能力。
8. `supportingAbilityIds`：輔助能力。
9. `representativeCourseIds`：最能解釋角色的代表課程。
10. `extendedCourseIds`：可支持該角色的延伸課程。
11. `fourYearFormation`：能力在一至四年級如何逐步形成。
12. `visibleOutcomes`：使用者可理解的作品、研究、企劃或行動成果。
13. `professionalDirections`：可能連接的專業方向；只能作介紹，不能承諾就業。
14. `matchingExplanation`：為何這些課程會指向此角色。
15. `source`：課程、設系文件、能力研究或設計推導來源。
16. `reviewStatus`：`draft`、`reviewed` 或 `approved`。

角色視覺可額外包含 `visualKey`、`props`、`palette`、`imagePath`，但必須等語意核定後再製作。

## 5. 學生收藏與角色生成邏輯

### 5.1 預期流程

1. 使用者在完整課程地圖中探索並收藏有興趣的課程。
2. 收藏頁持續顯示已選課程及其領域、年級與能力訊號。
3. 使用者主動選擇「看看我的學習角色」。
4. 系統只依實際收藏課程，計算最接近的 8 個專業角色之一。
5. 結果頁說明：命中的代表課程、形成的能力與仍可探索的方向。
6. 使用者可查看其他 7 個角色及其課程，但瀏覽不會改變收藏或當前結果。

### 5.2 匹配原則

- 同一收藏內容在同一規則版本下必須得到穩定結果。
- 每個結果都必須能用實際課程與能力解釋。
- 課程可同時支持多個角色，權重與角色作用不同即可。
- 不強迫每個角色擁有相同課程數，也不強迫四個年級平均分配；但應檢查四年形成是否合理。
- 收藏少於 3 門仍可使用，但結果應標示為「目前浮現的方向」，避免過度斷言。
- 不推論人格、性格、命運或學習優劣。
- 不使用隨機配對、假精準百分比、資格認證或就業保證。
- 角色結果應允許重新計算，但不要因查看其他角色而自動改變。

### 5.3 建議的映射資料結構

```ts
type CourseCharacterMapping = {
  courseId: string
  characterId: string
  abilityIds: string[]
  weight: number
  role: 'core' | 'supporting'
  reason: string
  source: string[]
  version: string
  reviewStatus: 'draft' | 'reviewed' | 'approved'
}
```

最終計分方式尚未決定。建立演算法前，先完成人工可讀的課程—能力—角色映射表，並以測試案例檢查是否有單一角色因課程數多而長期壟斷結果。

## 6. 建議資訊架構與版面角色

### 6.1 不要同時展示 12 個大型角色

- 首頁／入口：看見 4 個領域角色或四個領域場景。
- 領域頁：先說明領域目標、能力與學習成果，再進入課程及四年路徑。
- 完整課程地圖：保留 69 門課的查找、篩選、年級與學期關係。
- 我的課程：顯示收藏與專業角色揭曉入口。
- 專業角色圖鑑：瀏覽 8 個專業角色及其代表課程。

### 6.2 閱讀層次

1. 第一層：四大領域，快速建立整體輪廓。
2. 第二層：各領域目標、能力、人才與代表成果。
3. 第三層：四年課程安排與個別課程資訊。
4. 第四層：收藏後形成的跨領域專業角色。

角色是課程關係的轉譯，不應成為遮蔽課程事實的主角。

### 6.3 行動裝置原則

- 上下滑動為主要閱讀方式，不依賴複雜拖曳。
- 內容自然進場，物件只做少量、有意義的動態。
- 主要操作需單手可達，收藏與返回狀態清楚。
- 不以 hover 作為唯一資訊入口。
- 動畫不得延遲看課、篩選或返回。
- 支援 `prefers-reduced-motion`。

## 7. 視覺方向與暫停事項

使用者期望最終角色具有 **3D Q 版、富想像力、容易記住** 的特質；角色可透過奇想身份、工具與場景暗示能力，再以附註連回真實專業方向。

但是目前刻意暫停：

- 最終角色名稱。
- 角色長相、性別、服裝、道具與場景。
- 角色配色與 3D 材質規範。
- 12 張角色生圖提示詞。
- 開場動畫與角色揭曉動效。

原因：若專業語意與課程映射尚未核定，先定形象會反過來限制角色內容，並造成昂貴返工。

先前四張領域插畫與星空資產可作歷史參考，但使用者已明確表示部分插畫不夠親近，不能直接視為新版角色系統的核定美術。

## 10. 下一組建議執行順序

### 階段 A｜核定角色語意

1. 與決策者逐一檢查 P1–P8。
2. 每個角色用一句話回答「做什麼」「憑什麼與其他角色不同」。
3. 合併過度重疊角色，補上缺失的重要方向。
4. 將八個角色狀態由 `draft` 更新為 `reviewed`。

驗收：八個角色都能以不同核心問題、能力、成果和課程組合被清楚解釋。

### 階段 B｜建立學系能力架構

1. 讀取能力研究 metadata，先去除個資與組織識別資訊。
2. 依學系課程與目標聚合為少量能力類別。
3. 為每項能力撰寫學生看得懂的名稱、定義與可見行為。
4. 記錄來源與審核狀態。

驗收：能力類別不只是抽象詞，能連到課程活動和可見成果。

### 階段 C｜完成 69 門課映射

1. 以 `courseId` 而非課名建立映射。
2. 每門課標註領域、核心／輔助能力及支持的專業角色。
3. 同一課可重複映射，不必為分類整齊而只放一處。
4. 檢查所有課程皆可在完整地圖被找到；角色圖鑑不必平均收錄全部課程。
5. 檢查四年形成路徑與先後關係。

驗收：沒有遺漏課程、沒有更改官方課程事實、每個映射都有簡短理由。

### 階段 D｜匹配模型與測試

1. 先採透明加權規則，不急著使用 AI。
2. 建立少量典型與邊界收藏案例。
3. 檢查相同輸入穩定、少量課可解釋、跨域課能合理反映。
4. 檢查角色分布，避免課程數量最多的角色壟斷。
5. 設計同分處理及規則版本更新策略。

驗收：每個結果可指出哪些實際課程與能力造成配對。

### 階段 E｜命名與角色視覺

1. 為每個語意角色發展富想像力的角色身份。
2. 真實專業方向放在副標或說明，不強迫角色像職業制服公仔。
3. 建立共通的 3D Q 版比例、材質、光線、鏡頭、背景與色彩規則。
4. 先做 2 個差異最大的樣張，通過後再批次製作 12 個。
5. 保留一致性測試與影像來源紀錄。

驗收：遮住文字仍可分辨角色差異；加上文字後能準確連回課程與能力。

### 階段 F｜產品介面實作

建議順序：資料模型 → 角色圖鑑 → 收藏與匹配 → 結果解釋 → 四領域入口整合 → 動效與視覺精修。

不得先用華麗動畫掩蓋資料與資訊架構尚未完成的問題。

## 11. 驗收底線

### 課程事實

- 69 門課全部可存取。
- 課名、年級、學期、類型、學分與領域不得擅改。

- 能返回完整課程地圖，不被角色體驗困住。

- 手機主要流程可單手操作。

- 圖片有尺寸策略、替代文字與載入降級方案。
- 配對規則具版本、測試與可說明性。
