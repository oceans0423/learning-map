# PRD v2 審查意見

**審查對象：** `PRD_interactive_curriculum_learning_map_v2.md`
**審查日期：** 2026-10-07
**參照資料：** `course/人文跨域與應用學系必選修課清單.md`、`course/附件九之四：115系所增設調整計畫書格式_D2-3_1226 (2).md`

---

## 總評

方向正確，可以做。v2 已收斂為課程地圖，「基底 → 應用 → 整合」結構、六項能力、資料治理與隱私規格都清楚。

剩下的風險不在技術，主要有兩個：

1. **內容核定的工作量可能卡住上線時程。**
2. **手機上的操作選項太多，且彼此重疊。**

另有數處內部矛盾需要修正。

## 修改清單

### P1：內容核定與上線時程（決定能否趕上申請季）

**問題**

- MVP 要求 69 門課每個欄位都經核定，而 §12.1 規定 `verified: false` 不得發布。
- 115 學年才實施的新課程，大三、大四選修多數尚未開過，也沒有課綱，「典型活動」和「可能產出」老師只能推估。
- 54 門選修牽涉多位授課教師，包括兼任教師，逐門確認時程難以掌握。
- 若要支援 116 學年申請季（約 2027 年 2 月至 5 月），內容核定就是關鍵路徑。

**建議**

- [ ] 改成依欄位分級發布，取代整門課單一 `verified` 開關：

| 層級 | 欄位 | 核定方式 | 上線條件 |
|---|---|---|---|
| A | 課名、學期、學分、必選修 | 正式課清單 | 直接發布 |
| B | 基底／應用／整合作用、主要面向 | 課程委員會開一次會一併核定 | 第一階段 |
| C | 能力與層級、活動、產出 | 授課教師 | 先做 15 門必修與示例路徑用到的選修；其餘顯示「說明整理中」 |

- [ ] JSON 改為每個欄位各自記錄核定狀態，例如 `verification: { "role": "approved", "competencies": "draft" }`。
- [ ] §15 明訂：**由內容維護者預填草稿、教師核定**是允許的，不屬於「自動標註」。
- [ ] 新增分階段上線時程：第一階段為四年骨架、必修詳情、作用與面向；第二階段補齊選修詳情。

### P2：精簡互動控制

**問題**

高中生在手機上要面對三種檢視、六個興趣、三個面向、三條示例路徑、學期切換、收藏與分享。其中「興趣」幾乎就是面向再切細：

| 興趣 | 對應面向 |
|---|---|
| 文學閱讀與文化理解 | 基底 |
| 寫作與創作 | 寫作與創作 |
| 數位內容與互動、AI 與資料應用 | 數位人文與內容 |
| 地方文化與田野、策展品牌與文化企劃 | 文化與社會實踐 |

三套機制講的幾乎是同一件事。這會讓資料標註加倍，而且 v2 沒有定義三者同時啟用時的優先順序。

**建議**

- [ ] 合併為單一「面向」控制，選項為基底加三個應用面向，可多選。若需要更細的區分，用面向下的次標籤處理，例如數位面向下分「AI」與「互動」。
- [ ] JSON 刪除 `interests` 欄位，或改為面向下的 `subTags`。
- [ ] 示例路徑改成在選定面向後出現「看一個四年範例」，不與其他控制並列。
- [ ] 三種檢視改成**同一份課程清單的不同分組方式**，不另做版面：
  - 四年檢視：依年級、學期分組。
  - 基底與應用檢視：依作用分組，組內再依年級排序。
  - 能力檢視：選一項能力後，依年級列出相關課程並標示層級。
- [ ] 補上後兩種檢視在手機上的版面描述。v2 目前沒有寫，開發時會卡在這裡。

### P3：內部矛盾

- [ ] **§5.1「基底層包含必修主幹」不正確。** 必修中的「數位人文方法與應用」、「數位策展：理論與實務」屬於應用；「人文創新設計專題」、「實務實習」、「畢業專題製作」屬於整合。應改為「基底層包含大部分大一、大二必修」，並說明「作用」與「必選修」是兩個獨立的屬性。否則學生會以為必修全是文學課。
- [ ] **語文教育課程在資料中沒有位置。** JSON 規定每門課都要有 `primaryTrack`，但 §5.1 說語文教育類不歸入主要面向。需定一條規則，例如允許 `primaryTrack: null`，讓這些課只出現在四年檢視與完整清單中。
- [ ] **三條示例路徑都是「基底＋單一面向」，反而暗示分流。** 建議至少一條改為跨面向，例如「文學文化＋寫作＋數位」，直接展示可以自由組合。每條路徑也要標示只涵蓋系訂學分的一部分，避免被誤認為照修就能畢業。
- [ ] **測試與驗收在考學生會不會背專有名詞。** §16.2 任務 2 和 §17.2 期待學生說出「文學文化為基底，其他為應用與轉譯」，但 §4.1 自己也說不能假設學生懂「轉譯」。驗收應改為「能用自己的話說明文學文化課與應用課的關係」。介面上的「應用與轉譯」也需要白話標籤，例如「把讀到、學到的東西做成作品」。

### P4：次要事項

- [ ] **實際案例的對應**：前身學系作品與新課程不是一對一，案例要標示「前身學系相近課程作品」，不能直接掛在新課名底下。
- [ ] **保留模組欄位**：JSON 加回 `module` 欄位，記錄計畫書的正式模組（人文思維與方法、數位人文、文化創意與社會設計、文學創作與語文教育），方便日後對照與評鑑，介面上不需顯示。
- [ ] **未成年受測者**：§16 的測試對象多數未成年，需加上監護人同意書與知情同意流程。
- [ ] **返回鍵行為**：切換面向或檢視時只更新網址，不新增瀏覽紀錄；開啟課程詳情才新增一筆。這樣手機返回鍵會關閉詳情，而不是一路倒退到每一次篩選。
