## 1. 產品摘要

本產品是一個面向高中生的「互動式四年課程與學習地圖」。它不是完整學系網站，也不是選課、排課或能力評量系統。

產品需要讓使用者在短時間內理解：

1. 四年各階段主要學什麼。
2. 文學文化與人文方法如何形成共同基礎。
3. 課程如何延伸至三個應用探索面向。
4. 哪些課程屬於必修、選修，以及安排在哪個年級與學期。
5. 專題、實習與畢業製作如何整合四年的學習。

核心敘事：

> 從文學文化與人文方法出發，透過敘事創作、數位媒介及文化社會實踐，把所學轉化為作品、企劃與行動。

## 2. 產品目標

### 2.1 核心目標

- 讓高中生不必理解系所術語，也能看懂四年學習進程。
- 將 69 門規劃課程整理成容易閱讀、探索與比較的課程地圖。
- 清楚呈現共同基底、應用探索及整合成果之間的關係。
- 以精緻視覺與必要互動建立可信、具辨識度的招生溝通介面。
- 支援手機、平板與桌機，且手機不需橫向拖曳才能理解內容。

### 2.2 非目標

第一版不處理：

- 正式選課、排課與衝堂檢查。
- 學分試算、畢業資格及先修判定。
- 人格測驗、適系測驗或自動推薦。
- 能力分數與學習成效評量。
- 逐課能力標註與能力檢視模式（列為第二階段）。
- 示例路徑（列為第二階段）。
- 使用者帳號、登入及跨裝置同步。
- 收藏清單、Cookie、localStorage 或個人追蹤。
- 完整學系沿革、師資、職涯、招生 FAQ 或家長專區。
- 大量學生作品與案例管理。

## 4. 核心課程模型

### 4.1 三層學習結構

#### 第一層：共同基底

以文學文化與人文方法為共同基礎，涵蓋文本閱讀、文化理解、敘事表達、田野調查、研究方法及批判思考。

共同基底不是第四個應用面向，也不等於所有必修課。**必修／選修與課程作用是兩個獨立屬性**：必修中仍有屬於應用（如數位人文方法與應用、數位策展）或整合（如人文創新設計專題、實務實習、畢業專題製作）的課程。

#### 第二層：應用探索

課程可連結一個或多個探索面向，三個面向不代表招生分組、固定分流或正式選課建議。

> **面向名稱【待系所確認】。** 下列為建議採用之名稱（取自 CODEX 版，涵蓋範圍較廣），系所確認前以此為暫定標籤；確認後一次更新前台文案與資料 `primaryTrack` 值。

1. **敘事與創作**  
   包含散文、小說、詩歌、報導、文案、出版及跨媒介敘事。

2. **數位人文與媒介**  
   包含數位敘事、資料方法、AI 協作、互動媒介、空間人文及數位策展。

3. **文化與社會實踐**  
   包含地方創生、田野調查、文化資產、策展、品牌、節慶及社會議題實作。

語文教育相關課程仍出現在完整課程地圖中；本系不設「語文教育」探索面向，此類課程若無適合的主要面向，可不設定面向（`primaryTrack: null`），仍完整保留於四年地圖與課程清單。

#### 第三層：整合成果

透過專題、實習、策展、企劃及畢業製作，整合共同基底與不同面向的學習。

### 4.2 四年學習主線

> 探索與奠基 → 方法與表達 → 跨域實作 → 整合與展現

| 年級 | 學習重點 | 培養的能力（年級層級摘要） | 可能進行的學習活動 |
|---|---|---|---|
| 大一 | 建立人文、文本、文化與數位方法基礎 | 閱讀理解、文本分析、基礎表達與數位工具入門 | 閱讀分析、文化觀察、基礎表達與數位練習 |
| 大二 | 學習田野、研究、敘事及議題分析方法 | 田野研究、資料整理、敘事轉譯與議題分析 | 訪談、資料整理、故事企劃與議題分析 |
| 大三 | 進入專題、策展、實習及進階選修 | 企劃協作、媒介應用、策展與場域實作 | 數位內容、創作、文化方案、策展與場域實作 |
| 大四 | 統整所學並完成公開成果 | 綜合運用、專案完成、公開表達與成果整合 | 畢業專題、作品集、成果展演或文化提案 |

- 上述摘要用於說明整體學習進程，不取代正式課程綱要。
- 「培養的能力」為**年級層級摘要**，不是逐課能力標註；逐課能力與能力檢視列為第二階段（見 v2 §6）。
- 此欄文字仍須經系所走查確認後發布。

## 6. 核心互動需求

互動只服務一個目的：協助使用者理解課程及其在四年學習中的位置。第一版的核心問題是「如何看懂四年課程」，不是「可以用多少種方式探索」。

### 6.1 年級展開（預設露出部分內容）

- 提供大一至大四四個階段。
- 每個階段先顯示「學什麼／如何學／培養什麼能力／可能完成什麼」摘要。
- **預設狀態不是全部收合：**
  - 桌機：四年摘要同時可見，**大一課程預設展開**。
  - 手機：四年摘要依序排列，**大一預設展開**，其餘年級可點開。
- **必修直接顯示**；選修預設收合，並標示「選修（共 N 門）」，一鍵展開。
  - 若要在收合狀態露出選修，須採中性排序（照課程清單順序），不得暗示優先序或推薦。
- 避免 69 門課一次全部展開造成資訊過載。

### 6.2 學期切換

- 提供「全年／上學期／下學期」。
- 預設為全年。
- 切換只調整課程顯示，不改變整體頁面結構。
- 若課程為全年或學期尚未確認，應有明確標示。

### 6.3 結構圖即操作介面（強調模式）

**頁面上方的「共同基底 → 應用探索 → 整合成果」結構圖本身就是操作介面，不另外再做一組重複的面向按鈕。**

#### 強調，而非篩選

本控制採「**強調模式**」：符合條件的課程加強顯示，其他課程**保留並降低視覺強度**，不會消失。這符合產品理念——讓學生看見面向可以跨越四年，而非把課程切成互不相干的分組。

- 工程命名、無障礙文字與結果摘要一律用「強調」，不用「篩選」。
- 結果摘要寫成：「**已強調 N 門相關課程，其他課程仍保留顯示。**」不得寫「共 N 門課」，以免使用者以為畫面只剩 N 門。
- 命中 0 門時顯示「已強調 0 門相關課程」，不視為錯誤。

#### 可點區與作用

- 點**三個面向**（敘事與創作／數位人文與媒介／文化與社會實踐）：強調符合該面向的課程。
- 點**共同基底**：強調相關基礎課程。
- 點**整合成果**：強調專題、實習、策展及畢業製作等整合課程。

#### 面向符合規則

> 課程的 `primaryTrack` **或** `relatedTracks` 包含任一已選面向，即視為符合該面向條件。

- `primaryTrack: null` 的課程不符合任何面向，但仍以降低強度的方式保留顯示。
- 第一版不區分主要面向與相關面向的強調強弱，命中任一即同等強調。

#### 學期、面向與作用的組合邏輯（兩層）

> **第一層：學期決定哪些課程「可見」。**  
> **第二層：面向與作用決定哪些可見課程被「強調」（採 OR）。**

- 可見課程 = 符合目前學期（全年／上學期／下學期）者。
- 強調課程 = 可見課程中，符合**任一**已選面向或作用條件者（OR，因第一版目標是探索而非精密查詢）。
- 三個面向互為可複選；共同基底與整合成果各為獨立的「作用強調」切換，與面向可同時生效。
- **年級展開狀態不參與篩選或強調。**
- **「清除條件」只清除面向與作用強調，不重設學期與年級展開狀態**（使用者多半只想取消強調，不該被送回全年與大一）。

#### 共通規則

- 未選擇任何條件時顯示完整課程地圖。
- 共同基底及必修主幹在任何狀態下持續可見。
- 其他課程降低強度時仍須維持可讀對比、仍可點。
- 課程地圖上方只顯示目前條件與「清除條件」，不另做第二組面向按鈕。
- 所有狀態變化須同時透過文字、標籤或邊框表達，不只依賴顏色。
- 不使用「推薦你」「你最適合」等判定語言。

### 6.4 課程詳情

#### 課程卡第一層（標籤顯示層級）

「作用」與「面向」回答不同問題，**兩者都要顯示，不是二選一**：作用＝這門課在四年中的角色（基底／應用／整合）；面向＝這門課探索的方向。顯示優先序如下，避免卡片標籤過多：

- **必定顯示：** 課程名稱、必修／選修（主要標籤）、年級、學期、學分。
- **固定顯示作用：** 基底／應用／整合。
- **有 `primaryTrack` 時顯示主要面向**；`primaryTrack: null` 則不顯示面向標籤。
- **`relatedTracks` 不放在卡片，只在詳情顯示**，避免卡片擁擠。

#### 課程詳情（含空內容行為）

點擊後以側邊抽屜、對話框或頁內展開方式顯示。**所有課程卡維持一致可點**，即使 `summary`／`activities`／`possibleOutputs` 尚未核定或留空也能開啟詳情，至少顯示：

- 完整基本資料（課名、年級、學期、學分、必選修）。
- 課程作用（基底／應用／整合）。
- 主要面向與相關面向（`primaryTrack`、`relatedTracks`）。
- 「實際開課依當學年度課表」提醒與官方課表連結。
- 已有可靠資料（對應 `verification` 為 `approved`）時，才顯示簡短說明、典型活動或可能產出；未核定或留空則**不顯示該區塊、不以推測文字填補**，並以一行說明取代：
  > 課程詳細說明整理中，實際內容請依當學年度課表及課程大綱為準。

如此每張卡片操作一致，不會出現有的能點、有的不能點，或打開後是空白視窗。

關閉詳情後，須返回原本的捲動位置與強調狀態。

### 6.5 網址狀態與返回鍵

- 網址可記錄年級、學期、面向／作用條件及已開啟課程。
- 重新整理或分享網址後，可重建相同檢視狀態。
- **更新篩選條件時使用取代歷史紀錄的方式（`replaceState`）**，避免手機返回鍵逐一倒退每次篩選。
- **開啟課程詳情時新增一筆瀏覽紀錄（`pushState`）**，使返回鍵能先關閉詳情。
- 網址不得包含姓名、裝置識別資訊或其他個人資料。

## 7. 視覺與操作原則

### 7.1 視覺方向

- 整體感受應具人文氣質、當代感與學術可信度，避免制式校務系統風格。
- 年級是主要閱讀軸，探索面向是輔助辨識軸。
- 共同基底、應用探索與整合成果應有清楚層次，但不可讓使用者誤認為固定分流。
- 課程卡維持簡潔；詳細內容在使用者主動開啟後呈現。
- 避免將 69 門課做成必須縮放、拖曳或辨認大量連線的節點圖。

### 7.2 響應式

- 手機：單欄垂直閱讀、年級手風琴、篩選控制（結構圖）可收合或固定於易操作位置。
- 平板：一至二欄布局，保留清楚的年級順序。
- 桌機：可使用四欄或寬版時間軸，但不得犧牲文字可讀性。

### 7.3 動效

- 展開、篩選與詳情切換使用輕量動畫協助理解狀態變化。
- 動效不應延遲主要操作。
- 尊重系統的減少動態效果設定。

### 7.4 無障礙

- 所有主要功能可用鍵盤完成。
- 焦點樣式清楚，開關詳情後焦點回到原課程卡。
- 顏色不是唯一辨識方式。
- 文字及互動元件對比符合校方採用的無障礙標準。
- 按鈕、篩選狀態及展開狀態具正確的語意標記。

## 8. 課程資料規格

### 8.1 第一版欄位

```json
{
  "id": "course-example-01",
  "name": "地方創生與數位敘事",
  "year": 1,
  "semester": 2,
  "credits": 2,
  "type": "elective",
  "role": "application",
  "module": "數位人文",
  "primaryTrack": "文化與社會實踐",
  "relatedTracks": ["數位人文與媒介"],
  "subTags": ["地方與田野", "數位敘事"],
  "summary": null,
  "activities": [],
  "possibleOutputs": [],
  "offeringNote": "實際開課依當學年度課表",
  "sourceVersion": "115學年度",
  "verification": {
    "basic": "approved",
    "role": "approved",
    "track": "approved",
    "summary": "draft",
    "activities": "draft",
    "possibleOutputs": "draft"
  }
}
```

### 8.2 欄位規則

- `id` 必須穩定，不以課名作唯一識別。
- 課名、年級、學期、學分及必選修以正式課程清單為準。
- `role` 可為 `foundation`、`application` 或 `integration`；與 `type`（必修／選修）為獨立屬性。
- `primaryTrack` 可為三個探索面向之一，也可為 `null`（如偏教學／語言學課程）。
- 同一門課可有多個 `relatedTracks`，但介面不可因此暗示必須選擇固定路徑。
- `module`：計畫書正式模組（人文思維與方法、數位人文、文化創意與社會設計、文學創作），供行政對照與未來評鑑；**前台不顯示**。原計畫書「文學創作與語文教育」模組在本產品記為「文學創作」。
- `subTags`：面向下的次標籤，供未來擴充搜尋或細分；**第一版前台不顯示**。
- `summary`、`activities`、`possibleOutputs` 沒有可靠資料時可留空，前台不顯示空區塊。
- 資料需保留適用學年度（`sourceVersion`）。

### 8.3 欄位級核定狀態（`verification`）

- 每個欄位各自記錄核定狀態（`approved`／`draft`），取代整門課單一開關。
- **非 `approved` 的欄位不得以事實呈現**，前台改為留空或不顯示該區塊，避免草稿被誤當正式內容。
- **第一版上線只要求 `basic`、`role`、`track` 為 `approved`**；`summary`、`activities`、`possibleOutputs` 可維持 `draft` 或留空，不因此隱藏整門課的基本資料，也不阻擋上線。
- 允許內容維護者預填草稿，再由系所或教師核定為 `approved`；此預填不屬於「自動標註」，但未核定前一律標為 `draft`。

## 10. 內容治理（最小規則）

不採用 v2 完整治理流程，但第一版至少須明定下列責任，避免上線後無人維護：

| 項目 | 負責 |
|---|---|
| 課名、年級、學期、學分、必選修 | 系所課程負責單位（依正式課程清單） |
| 課程作用（基底／應用／整合）與探索面向 | 課程委員會一次核定 |
| 課程簡介、典型活動、可能產出 | 授課教師（第一版可留空） |
| JSON 資料、版本日期、網站內容更新 | 指定一位內容維護者（最終內容負責人，避免多版本衝突） |
| 部署、HTTPS、備份與資安 | 資訊單位 |

共同規則：

- 課程資料每學年度正式課程確認後至少全面檢查一次；課程異動時同步更新。
- 網站清楚標示資料適用學年度及更新日期。
- 規劃課程不等於當學期實際開課；一律顯示「實際開課依當年度課表」。
- 沒有可靠資料的欄位保持留空，不以生成或推測文字填補。

## 11. 驗收標準

由於時程不安排正式使用者測試，第一版以內容、功能及介面檢核為主。

### 11.1 內容

- 69 門課程均可追溯至正式課程清單。
- 課名、年級、學期、學分及必選修資料正確。
- 網站清楚標示資料適用學年度。
- 所有頁面均顯示或可找到「實際開課依當學年度課表」。
- 沒有資料的課程不以生成或推測文字填補。
- 30／26 學分差異在上線前獲得確認或有適當說明。
- 面向名稱已由系所確認並與前台一致。

### 11.2 理解（系所走查）

由系所內容負責人進行上線前走查，確認首頁在**不操作**的情況下即可看出：

- 四年學習的先後進程。
- 文學文化與人文方法是共同基礎。
- 三個探索面向不是固定分組。
- 專題、實習與畢業製作具有整合作用。
- 必修與選修之間的差異。
- 「應用與轉譯」等詞皆有白話標籤，不要求讀者理解專有名詞。

### 11.3 互動

- 年級及選修內容可正確展開與收合，大一與必修預設可見。
- 學期切換結果正確。
- 結構圖可單選、複選面向與作用條件並清除。
- 強調後共同基底與必修課仍可辨識。
- 課程詳情可開啟、關閉並回到原位置。
- 分享或重新整理網址可重建檢視狀態；返回鍵先關閉詳情、不逐一倒退篩選。
- 手機不需橫向縮放或拖曳即可完成主要操作。
- 鍵盤可操作所有核心功能。

### 11.4 品質

- 正式環境無阻斷操作的錯誤。
- 常見手機與桌機寬度沒有內容截斷、重疊或不可操作元件。
- 首屏內容及主要課程地圖具有合理載入速度。
- 基本 SEO、分享預覽、HTTPS 及錯誤頁設定完成。

## 14. 產品原則

1. **先讓人看懂，再提供更多功能。**
2. **年級是主軸，面向是探索工具。**
3. **共同基底不能被應用面向淹沒。**
4. **不把探索面向呈現成固定分流。**
5. **不把規劃課程誤寫成每年必然開設。**
6. **沒有可靠資料時，少寫比推測更可信。**
7. **互動必須幫助理解，不為互動而互動。**

---

## 15. 最終交付定義

第一版交付的是一個可公開、精緻且容易理解的四年課程地圖。使用者進入網站後，不需登入、不需測驗，也不需先做選擇，即可看見完整學習結構（且大一與必修已預設露出）；並能透過年級、學期、結構圖面向強調及課程詳情逐步理解 69 門課程。

第一版的成功不以功能數量衡量，而以課程結構是否清楚、資料是否可信、手機操作是否流暢，以及整體呈現是否足以代表學系特色為準。長期能力檢視、示例路徑與作品案例的資料基礎已於 `verification`、`module`、`subTags` 中預留，待第二階段依 v2 擴充。
