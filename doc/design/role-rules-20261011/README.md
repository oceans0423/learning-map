# 探索角色本機判讀原型

本輪完成資料化與可重現測試；未接入首頁、收藏頁或正式網站，未修改原始 69 課程。使用 UX Architect 的資料契約方法分離人工標註、來源載入與純判讀函式，不套用其主題切換或行銷版面預設。技能所提 `ai/agents/architect.md` 在本專案不存在；本輪依可取得的技能及專案文件工作。

## 執行

在專案根目錄：

```powershell
node --test doc/design/role-rules-20261011/interpret.test.mjs
node doc/validation/verify-character-mapping.mjs
node doc/design/role-rules-20261011/inspect.mjs course-013 course-031 course-032
```

沒有額外依賴或安裝；以上指令只讀取檔案、執行並輸出到終端，不寫入檔案或瀏覽器收藏。最後一例輸出 P1／P2 雙方向及逐課理由。未帶課程 ID 則輸出線索不足。

## 檔案與契約

- `annotations.mjs`：八角色必要面向及 84 筆人工標註。以「角色＋課程＋工作面向＋能力 ID」儲存，不靠課名關鍵字或 H 標籤數量推論。
- `load-data.mjs`：從對照 Markdown 載入代表／支援、理由、限制與來源行號，合併人工標註，核對課名、能力引用、關聯完整性及 69 課覆蓋。資料只在記憶體建立，不維護第二份逐課理由副本。
- `interpret.mjs`：純函式 `interpretCollection(courseIds, data)`；不操作 DOM、localStorage 或網路，也不生成隨機結果。
- `inspect.mjs`：命令列檢視結果。
- `interpret.test.mjs`：與既有情境文件對照的 20 組預期，以及邊界／不變性檢查。

`loadRoleData()` 回傳結構化物件：schema／關聯／標註版本、來源摘要、全部有效 ID、角色定義、84 筆關聯、3 筆待題目確認課程。來源摘要包含對照表、能力文件、課程、標註、判讀程式與情境規格，可辨識資料或規則變更。

判讀輸出包含：有效且排序去重的收藏快照、忽略的未知 ID、非字串項目數、四種結果狀態、候選方向、片段方向、待確認課程，以及版本與來源摘要。每方向附代表線索狀態、必要面向的課程／能力來源、缺少面向、逐課理由及限制。結果為獨立副本，修改結果不改動來源資料。

## 本輪形式化的規則

候選方向須同時符合：

1. 實際收藏含該角色至少一筆代表關聯。
2. 該角色所有必要工作面向都有人工標註的課程依據。

這是前版定性判準的第一個可執行版本，仍屬設計原型，沒有經實際學生驗證。它是內容完整性條件，不是最低課數或能力達標門檻；一課可以涵蓋多面向，支援課也可補面向，但全為支援仍不配角色。

候選數 0／1／2／3 以上對應 insufficient／single／dual／multiple。方向固定按 P1–P8 呈現，不排名。沒有分數、權重、適配百分比、跨域數量加成、主角決勝或課程解鎖。

P8 的永續反思是補充面向，不冒充實踐或共創；候選仍附「未證實地方共同決策與執行訓練」。H07 學習引導、H08 分析與 H13 地方情境都透過逐角色標註及既有理由／限制區分，不能由頂層能力 ID 自動擴張。

## 驗證紀錄與界線

本輪 `node --test`：28 項測試通過。其中 20 項為既有情境，另涵蓋移除依據、基礎課數不決勝、全部收藏、單課、無效輸入、輸出隔離及支援課反例。

不變性測試逐一檢查全部 69 個單課及 2,346 個不同兩課組合，共 2,415 組：調換順序、重複 ID 不改結果；引用的每筆課程及能力面向可回查實際收藏。這不是窮舉全部收藏組合，也不是驗證每組的教育語意正確。

原結構檢查再次通過：69 課、8 角色、84 關聯，原課程檔 SHA256 不變。

測試證明的是實作與本版規劃一致、沒有部分資料與狀態錯誤；不證明角色是人格測量、正式能力評估或生涯適配結果。標註、代表／支援與必要面向仍可能隨課綱、學系審閱及學生測試調整。修改標註或規則時需更新對應版本、重新測試，不能只改預期讓測試變綠。
