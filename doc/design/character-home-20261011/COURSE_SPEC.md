## 完成內容

首頁已確認的造型、色彩與人物版面保留。四領域入口直接前往帶領域條件的課程頁，全部課程入口不預設任何條件。瀏覽器返回首頁保留人物選取與原捲動位置。

課程頁涵蓋搜尋、領域複選、年級與必選修篩選、結果數、可重設的零結果狀態、讀取失敗重試、基本資料詳情、主要能力與可展開的支援方向。篩選以網址保存，可重新整理或分享該網址。

## 資料與假設

- 69 門課直接讀取 `doc/course/courses_v1.json`，保留課名、ID、模組、年級、學期、學分、必選修、開課備註及版本，不修改該檔或正式網站資料。
- 課程按年級、學期、永久 ID 排序；不是先修路徑。尚未建立實際先修關係，不以箭頭假造依賴。
- 學系顯示領域「敘事與內容創作」仍對應原模組「文學創作」，不重寫原始分類。
- `build-abilities.mjs` 從既有 `doc/DEPARTMENT_ABILITY_MAPPING_2026-10-11.md` 生成 `ability-data.json`，驗證 14 名稱、69 ID 與課名、所有能力引用。未讀取／複製私有訪談原文與企業資訊；也沒有公開原研究資料。
- 能力名稱採已確認的學系轉譯；逐課關聯與成果例仍標示「課程對應規劃」。核心與輔助是建議方向，不是權重或熟練程度，不將成果建議冒充既定作業。
- 每門詳情先顯示原表 1–2 個核心能力；其餘以支援方向展開。保留原表理由中的子面向限制，不由頂層標籤推算角色。
- 沒有補寫缺少的 summary、activities、possibleOutputs，也未建立收藏、推薦排名、能力分數、人格測驗或個人角色生成。

## 取捨與下一階段

目前為清楚、完整的課程瀏覽，不做大型圖譜或複雜拖曳畫布。好處是手機易讀、鍵盤可操作、條件可分享；代價是學年間的學習關聯尚未視覺化。四領域與年級可先協助理解安排，後續再以已確認的能力對照建立關聯視圖。

不在本輪做角色計分：H07、H08、H13 含不同子面向，單純累計頂層能力會誤導。下一步可先討論「收藏後如何呈現感興趣的學習方向」，再確定個人角色的產生規則。

- `verify-courses.mjs`：69 課名與詳情事實逐一核對；69 核心能力與理由逐一比對衍生資料；複選交集、全形英數、URL 還原、零結果清除、支援方向展開、失敗重試及能力檔失敗降級。
- 320、390、700、768、1024、1440px 檢查整頁水平溢出；手機詳情容器不橫向溢出；Chrome 無 JavaScript 執行錯誤。
- 報告：`validation/results.json`、`validation/courses-results.json`。截圖：`courses-desktop.png`、`courses-mobile.png`、`course-detail-mobile.png`。
- 限制：Chrome 自動化及模擬視窗，不等於實體手機／Safari／讀屏／高中生測試，也不宣稱全面無障礙認證。

UI Designer 技能在本輪促成共用色彩、字級與元件狀態的延續，並要求把回退狀態、焦點與手機規格一起交付。
