# 收藏與我的探索｜第三階段

## 導覽辨識修正

使用者指出頁首「首頁／找課程／我的探索 0」不明顯。本次僅加強此區塊，未改已確認的首頁及課程內容布局。

- 採 Visual Hierarchy（UI-02-023）、Touch Target（UI-15-007）、Focus Indicator（UI-15-003）：目前頁面改深綠 #3c5745 底、#fffdf8 反白、較粗文字及底部內線；其餘使用淺底與 1px 邊框，讓可點擊範圍明確。
- 桌面字級 15px、控制項至少 48px 高；手機 12–13px、三欄自適應、48px 高；收藏數改為附單位的「0 門」，不是不明用途的單一圓點。
- 導覽仍是原生跨頁連結及 `aria-current="page"`，不偽裝為 ARIA tabs；焦點另有 3px 藍框，不與目前頁面的綠底混淆。沒有新增動畫。
- 取捨：比文字連結稍有視覺重量；以既有墨綠及暖白維持一致，避免只靠細底線。UI Designer 技能促成狀態與可點擊範圍的一致處理。
- `verify-navigation.mjs` 測試兩頁目前狀態、320–1440px 七種寬度、48px 高度、整頁與文字無溢出、鍵盤 Enter 與焦點、收藏門數同步。報告及局部截圖在 `validation/navigation-*`；未做實機或使用者辨識測試。

## 本輪完成

在第二階段已確認的課程探索頁上新增可選用的收藏。卡片、課程詳情與導覽門數同步；「我的探索」顯示收藏課程、四領域分布，以及可追溯到來源課程的能力方向。

## 能力資料的解讀界線

- 只使用既有 `ability-data.json` 的學系課程對應規劃，未重新發明能力或讀取私有訪談資料。
- 四領域門數是收藏課程的原模組統計；不是個人領域能力。
- 每項能力的門數是含主要或支援連結的不同收藏課程數，同一課程最多計一次。主要與支援標示仍保留，不轉換成權重。
- 能力方向以原本 H01–H14 順序呈現，不以次數判定重要性、人格、熟練程度或角色。
- H07／H08／H13 子面向未建立完整機器可讀標註，本輪不計分、不直接配對八角色、不宣稱學生已具備能力。
- 增加或移除收藏只改使用者的探索清單，原始 69 門課程、能力架構與對照文件不變。

## 保存假設與取捨

- 假設目前不做登入與後端。使用相同瀏覽器、相同網站位址（含埠號）的 localStorage；不同裝置、不同瀏覽器、不同預覽位址不共享。
- 專用 key：`humanities-character-prototype:collection:v1`。只保存 `{version:1, ids:[...]}`；不保存姓名、訪談內容、能力分數或角色結果，不送往伺服器。
- 只接受目前 course-001–course-069 的 ID，去重並忽略失效項目。來源資料未被覆寫。
- 讀取或寫入失敗改成本頁記憶體操作，明示重新整理／離開可能遺失；不承諾跨頁暫存。毀損記錄由使用者明確確認後才可清除。
- 同源分頁使用 storage 事件更新。每次修改先讀取最新專用清單，保留其他分頁已完成的逐次修改；localStorage 不是交易資料庫，極端同時寫入仍可能有最後寫入覆蓋的限制。若未來需要可靠多裝置協作應改後端或交易式儲存。
- 清空只移除專用 key，不呼叫 localStorage.clear，也不遷移或清除正式網站的儲存。
- 保存簡單且免登入，代價是無雲端備份；已在介面持續說明清除瀏覽器資料會移除收藏。

## 驗證

`verify-collection.mjs` 在獨立自動化瀏覽器情境測試，不讀寫使用者日常瀏覽器的收藏。

涵蓋：空狀態、卡片／詳情同步、重新整理、能力來源集合逐一比對、六種視窗寬度、移除後焦點、跨分頁同步、取消與確認清空、保留無關 key、鍵盤與快速切換、減少動態、讀取／寫入／清除失敗、毀損資料、重複／失效 ID、能力檔失敗降級及 JS 錯誤。

報告：`validation/collection-results.json`。截圖：`collection-desktop.png`、`collection-mobile.png`。首頁與第二階段測試亦已回歸通過。

限制：Chrome 自動化與模擬視窗，未實體手機、Safari、讀屏軟體或高中生測試，不宣稱完整無障礙認證。
